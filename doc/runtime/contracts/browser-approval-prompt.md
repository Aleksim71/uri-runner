# Browser approval prompt

## Назначение

Этот документ задаёт **единый формат confirm-запроса** для browser действий в A19.

Confirm нужен не как формальность, а как прозрачная часть протокола между URI, пользователем и Максом.

---

## Когда использовать

Browser confirm нужен, если действие:

- открывает URL;
- запускает браузер URI;
- reload-ит страницу;
- переключает вкладки;
- запрашивает trace/performance capture;
- выходит за SAFE-границы A19.1.

---

## Обязательные поля confirm-запроса

URI должен сообщить:

- **Цель**
- **Действие**
- **Почему это нужно**
- **Риск**
- **Команды / browser operations**
- **Ожидаемый результат**

---

## Рекомендуемый шаблон

```text
BROWSER CONFIRM
────────────────────────
Цель: <что хотим понять или получить>
Действие: <что именно будет сделано>
Почему это нужно: <почему без этого шага не обойтись>
Риск: низкий | средний | высокий
Операции: <attach / open url / reload / trace / ...>
Ожидаемый результат: <какие данные или эффект ожидаются>
```

---

## Пример 1 — запуск browser instance

```text
BROWSER CONFIRM
────────────────────────
Цель: получить browser diagnostics для локального frontend
Действие: запустить отдельный диагностический browser instance URI
Почему это нужно: браузер ещё не подготовлен вручную, attach не к чему выполнять
Риск: средний
Операции: launch browser -> open local url -> attach
Ожидаемый результат: доступная diagnostic session и safe browser artifacts
```

## Пример 2 — reload страницы

```text
BROWSER CONFIRM
────────────────────────
Цель: проверить, воспроизводится ли runtime error после перезагрузки
Действие: reload страницы в диагностической вкладке
Почему это нужно: нужно подтвердить, что ошибка возникает на чистой перезагрузке
Риск: низкий
Операции: reload page -> re-collect console/errors
Ожидаемый результат: обновлённые console/errors artifacts
```

---

## Что не должно происходить

- Нельзя маскировать FORBIDDEN-действия под обычный confirm.
- Нельзя пропускать объяснение риска.
- Нельзя смешивать confirm-текст с raw attach/collect логикой.

---

## Короткий итог

Browser confirm должен быть **коротким, конкретным и проверяемым**:
пользователь должен понимать, **зачем** действие нужно и **что именно** будет сделано.
